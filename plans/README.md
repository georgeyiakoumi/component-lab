- **Slow-path round-trip test gap**: Not a finding — `lib/parser/__tests__/slow-path.test.ts` has 4 thorough test suites covering mutations.
- **Shiki re-imported on every panel open**: Misleading — dynamic `import()` is cached by the JS module system after first load.
- **Path traversal defense in parse API**: Correctly implemented with dual-layer defense (regex + resolved path check).
- **Input validation on component creation form**: Client-only localStorage; validation is advisory until server persistence arrives.
- **Rate limiting on parse API**: Netlify provides infrastructure-level rate limiting; low priority for a tool app.
- **God modules (component-source.ts, style-controls.tsx, define-view.tsx)**: Real debt but L effort with MED risk — not worth a plan until a specific refactoring need arises. Noted for future work.
- **Tailwind options static lists**: Could be auto-generated but MED effort with MED risk and no immediate payoff.
- **Inconsistent persistence patterns (localStorage vs. planned Supabase)**: Real gap but premature to abstract until M5 auth work begins.
- **Legacy v1 tree migration E2E test**: Nice-to-have but low probability of regression given unit test coverage.
- **PERF-03 O(37) lookups per render**: Wrong — both `previews` and `templates` are Record objects with O(1) key lookups.
- **CORRECTNESS-05 Stale portal container ref**: Callback ref pattern is correct; `canvasEl` state triggers re-render, `canvasRef.current` is always in sync.
- **SECURITY-01 Shiki dangerouslySetInnerHTML**: Shiki output is safe by design; code input is app-generated, not user-submitted.
- **SECURITY-02 localStorage plaintext**: Known and documented; Supabase migration planned. Not actionable now.
- **ARCH-05 Data-attr consistency**: Valid concern but M7 scope — style editor doesn't yet write data-attr classes.
- **ARCH-03 God object parallel monoliths**: Real but design decision for M7+ — current approach is readable and works. Not worth refactoring before tests exist (plan 013).
